# 角色关系与信息差档案

## 1. 八名角色

| 角色 | 电影关系/身份 | 主要张力 | 游戏叙事职责 |
|---|---|---|---|
| Emily | 视角中心；Kevin 的伴侣 | 对关系未来犹豫；对 Laurie 出现敏感 | 玩家认知中心、调查者、最终选择承担者 |
| Kevin | Emily 的伴侣；Laurie 的前任 | 同行出差提议、旧情与当前关系 | 关系主线、身份核验参照 |
| Mike | 聚会主办者之一；Lee 的伴侣 | 演艺事业受挫、自尊、旧秘密 | 房屋主人、群体冲突中心 |
| Lee | 聚会主办者之一；Mike 的伴侣 | 职业发展与伴侣关系 | 聚会稳定锚点、独立人物视角 |
| Beth | Hugh 的伴侣；与 Mike 有过去 | 对异常的解释方式、旧关系秘密 | 线索解释差异、关系信息差 |
| Hugh | Beth 的伴侣；有物理学家兄弟 | 理性解释异常 | 理论资料来源、证据链参与者 |
| Amir | Laurie 的约会对象/伴侣关系 | 群体关系与异常压力 | 早期外出、盒子和照片线索链 |
| Laurie | Kevin 的前任；由 Amir 带来 | 与 Emily 的紧张、Kevin 的旧情 | 关系压力、群体观察者 |

电影对某些关系的称谓和亲密程度不总是完全明确。不要擅自把约会写成婚姻或长期承诺。

## 2. 关系网络

### Emily—Kevin
电影事实：两人正在交往；Kevin 希望 Emily 考虑同行出差；两人有未解决的关系议题。Kevin 与 Laurie 曾交往。游戏设计：关系至少区分信任、坦诚、承诺压力、当前冲突，不简化成单一好感度。

### Kevin—Laurie—Amir
Kevin 与 Laurie 是前任；Amir 带 Laurie 参加聚会。Laurie 与 Kevin 的互动可能影响 Amir 和 Emily，但不能默认 Amir 知道全部情况，也不能自动推定角色动机。

### Mike—Lee
两人共同主办聚会。Lee 不能只作为 Mike 的附属角色；应有独立态度、信息和选择。

### Hugh—Beth
两人是伴侣。Hugh 倾向理性解释，Beth 对灵性/能量等解释较开放。同一线索可以产生不同解释。

### Mike—Beth
电影揭露两人过去存在秘密关系。Emily、Hugh、Lee 等人何时知情必须分别记录。

## 3. NPC 必须分开的四种状态

1. **经历 Experience**：这个具体 NPC 副本亲自经历过什么。
2. **知识 Knowledge**：当前掌握的信息及来源。
3. **判断 Belief**：对未知事实的解释，允许错误。
4. **表达 Disclosure**：愿意告诉 Emily 什么，受关系、风险和场景影响。

不能把四者合并成一个 `knows` 布尔值。

## 4. Emily 的认知

- 观察：亲眼看到的物件、人物、空间变化。
- 听闻：在场听到的对话，记录说话者和是否直接听见。
- 阅读：便条、照片、书籍等内容。
- 推断：根据证据形成的解释，记录置信度/未确认状态。
- 更正：新证据推翻旧判断时，保留旧推断及更正原因。

例如：看到照片与记忆不同是观察；“照片来自另一个现实”是推断。

## 6. NPC 副本身份模型（游戏设计）

每个实例至少需要概念字段：
- `character_id`：角色原型，如 `kevin`。
- `instance_id`：当前现实中的具体个体。
- `world_id`：当前归属现实。
- `experience_log`：经历事件 ID。
- `knowledge_ids`：掌握信息。
- `belief_ids`：推断/信念。
- `relationship_state`：关系状态。
- `disclosure_state`：已向 Emily 透露的内容。

现实切换不能只替换角色模型和名字，必须能解释人物为何如此回答。

## 7. 待定

- 副本是否共享跨现实记忆。
- NPC 是否能通过梦境或传闻获得其他现实信息。
- 玩家分享线索后 NPC 是否必然相信。
- 关系状态是否允许永久关闭话题。建议避免早期永久封锁。
