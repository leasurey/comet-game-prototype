## 二、聚会房屋空间关系说明

**前提**：以下连通关系以"影片中人物动线不矛盾"为依据，**不代表电影给出了确定户型**。

电影呈现的空间逻辑（B/C 级为主）：

```
街道 ── 车道 ── 门廊 ── 前门 ── 门厅/走廊
                                    │
                    ┌───────────────┼───────────────┐
                    │               │               │
                 客厅            餐厅/餐桌         厨房
              （沙发·壁炉）      （8 人长桌）      （备餐·取酒）
                    │               │               │
                    └───────┬───────┘               │
                            │                       │
                        露台门 ──────────────── 后门（可能）
                            │
                          露台 ── 后院
                            
              走廊侧：卫生间 / 地下室门 / "door to nowhere"
```

**三点需要明确的判断**：

1. **客厅—餐厅—厨房 三者关系**：影片中人物在三处之间频繁走动且不需要绕行，
   支持"三者为连续开放空间"或"以宽门洞相连"。这是 B 级判断，**不是 A 级事实**。

2. **"door to nowhere"**：影片中它被明确讨论为打不开的门。
   但它位于哪面墙、背后是什么结构，**电影没有给出可确认的答案**。
   在游戏中它应作为**叙事装置**存在（可交互但打不开），
   其位置属于 D 级（原创布点）。

3. **地下室**：仅有对白提及，无任何画面。
   本轮灰盒**不制作地下室内部**，只保留一个封闭门作为暗示（D 级）。

## 五、当前场景构建器需要修改的文件清单

### 5.1 现状（已核实）

```
tools/scene_builder.gd     驱动器，注册 3 个场景名
tools/scene_content.gd     全部场景内容 + 全部 helper（约 560 行）
```

现有 helper：`_mat` `_n` `_box` `_solid` `_cyl` `_omni` `_sun` `_world_env` `_spot` `_col` `_commit`

**已识别的能力缺口**：

**① 无法开洞的墙**
当前只有 `_solid()` 生成整块 Box。做房间必须有门窗洞口，
否则要么墙体不封闭（漏光、玩家能穿）、要么把整面墙做成碰撞体堵死门。

**② 缺少房间级组织**
`scene_content.gd` 已有 560 行，若继续堆入一个 16×11 m 的房屋，
单文件会失控，且无法满足任务书"几何、碰撞、灯光、装饰分别组织"的要求。

## 六、灰盒实施方案

### 6.1 分三步走（每步可独立验收）

**第 1 步：骨架与通行（优先）**

1. 实现 `geom.gd` 的 `wall_with_opening()`：把一面墙拆成若干 Box 段，
   留出门窗洞口，每段独立生成 StaticBody3D + BoxShape3D。
2. 用外墙 + 内墙拼出 5 个房间的封闭外壳。
3. 开门洞、放玩家 spawn。
4. **验收**：能走遍所有房间，不穿墙、不漏出屋外、不卡门口。

**第 2 步：家具与比例**

5. 用 `props.gd` 摆放餐桌椅、沙发组、厨房岛台与操作台。
6. 按 3.5 的净宽表逐条核对通道，尤其是沙发—咖啡桌 0.85 m。
7. **验收**：所有通道可通行；家具挡得住人；不出现"能钻进桌子"。

**第 3 步：灯光与停电变体**

8. 用 `light.gd` 布正常照明。
9. 生成 `Variant_world_alpha`（有电）/ `Variant_world_beta`（停电）两套。
10. **验收**：切换世界时灯光正确整体切换；停电后仍能辨认空间轮廓。

### 6.2 墙体开洞的实现要点（本轮最关键的技术点）

一面 5 m 宽的墙，中间开 1 m 门洞，正确的做法是拆成三段而不是"一个大盒子挖洞"：

```
   [墙段A 2.0m] [门洞 1.0m] [墙段B 2.0m]
                  ↑
            门楣段（洞口上方 0.55m 高）
```

即：**左右两段 + 上方门楣段**，共 3 个 Box。
这样既保证碰撞连续（玩家撞墙不穿、走门口不卡），又不影响视觉。

必须注意：**每段都必须独立带碰撞**，否则门洞边缘会出现可以穿过的缝隙。

### 6.3 灰盒的视觉基调

- 全部使用 `StandardMaterial3D` 纯色，不加载任何贴图
- 墙：浅灰米色；地板：深木色；天花板：近白
- 家具：低饱和灰蓝/棕，便于后续替换
- 不追求好看，只追求**空间可读**：能一眼看出这是客厅、那是餐厅

| 2 | **遮挡判定首次面对大量墙体** | 室内热点可能被墙误判为遮挡 | 热点碰撞盒必须露出墙面（贴着墙面向房间内偏移 ≥ 5 cm） |
| 3 | **房间多导致碰撞体数量上升** | 从 19 个涨到 80+ | 预计仍远低于性能瓶颈，但需实测帧率 |
| 4 | **玩家 spawn 落在家具内** | 出生即被顶出或卡死 | spawn 必须放在净空中心，且要逐个房间核对 |
| 5 | **天花板遮挡视线** | 室内仰视时射线打到天花板 | 热点不放在天花板上即可 |
| 6 | **场景重建覆盖手工调整** | 在编辑器里改的 tscn 会被下次构建冲掉 | 所有调整必须回到 `tools/house/*.gd` 源码 |
| 7 | **两层世界变体重复几何** | 灯光变体若把几何也复制一份会翻倍 | 几何放 `Shared`，只有灯光放 `Variant_*` |
| 8 | **家具碰撞盒过大导致"隔空撞墙"** | 手感差 | 碰撞盒贴合体块，椅子的碰撞盒可比视觉略小 |
| 9 | **餐桌 8 椅占用空间** | 拉椅子的空间不足，显得挤 | 桌边到墙 ≥ 1.35 m，长边各 3 椅 |
| 10 | **中文路径 + 大量新文件** | 构建脚本路径拼接出错 | 全部用 `res://` 相对路径，避免绝对路径 |
| 11 | **现有 3 个场景的回归风险** | 改动 helper 可能影响旧场景 | `lib/` 为新增文件，旧场景继续用 `scene_content.gd` 内部 helper，互不引用 |
