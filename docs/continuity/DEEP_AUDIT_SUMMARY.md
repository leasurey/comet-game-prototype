## 二、任务十三最终九问

**1. NPC 是否具备真正的自主行为和持久状态？**
都没有 [A]。行为：移动 API 无游戏调用者，NPC 全程站桩（CT-020）。持久：serialize 只有位置/朝向/行为三字段且读档不消费（CT-003），离场即销毁重建（CT-004）。navmesh 寻路/避让引擎能力就绪 [B]，但没有"大脑"。

**2. NPC 记忆、关系真实存在还是预留？**
比预留更空：**连字段都没有** [A]。对话也无 said 记录（CT-023）。

**3. 玩家认知是否真正与客观世界分离？**
**是** [B]。C1 断言世界切换零授予；learn 只由 inspect/dialogue 两入口写；来源/现实/tick 齐全且入档可恢复（C5）。分离原则是当前四大系统里执行得最好的一条。

**4. 对话是否受认知、现实、NPC 状态影响？**
只受**玩家认知**影响 [A+B]；现实与 NPC 状态完全不影响 [A]。且认知影响本身被 CT-019 打断：9/29 节点的钥匙不存在。

**5. 四大系统能否完整保存并恢复？**
世界/事件/玩家/认知：**能** [B]。NPC：**不能**（写而不读）[A]。对话进度/手机：无状态可存 [A]。答案是"两个半"。

**6. 当前最严重的三个系统连接断点？**
① **钥匙断供**（CT-019）：认知→对话的因果链在真实游玩中失效；② **NPC 状态生命周期断裂**（CT-003/004）：存档与场景重入都保不住 NPC；③ **事件输出单线**（CT-005/022）：玩家行动与 NPC/物品/对话之间没有事件通道（链路 B 全断）。

**7. 哪些已完成、哪些基础实现、哪些空壳？**
- **已完成**（机制+测试）：FPS 移动/跳跃、场景切换（门级落点）、热点交互、现实循环、原子存档、认知核心（分离/来源/入档）、对话分支引擎+面板、navmesh 寻路/避让、音频状态响应（现实音/环境音/脚步）。
- **基础实现（能跑但不完整）**：认知-对话闸门（钥匙断供）、NPC 状态序列化（无恢复）、事件系统（只连世界线）。
- **空壳/不存在**：NPC 记忆/关系/情绪、NPC 自主行为、手机、对话进度、物品状态、observe/infer 入口、空间音频。

**8. 哪些必须先修，哪些可等剧情？**
- **必须先修**（否则剧情内容无处安放）：CT-019（钥匙）、CT-003/004（NPC 生命周期）、CT-001/002（输入锁）、CT-005（interact 事件线）。
- **可与剧情并行**：各现实台词差异（D）、停电/照片等内容（D）、空间音频（CT-012）、UI 音效（CT-007）。
- **可最后**：死信号清理（CT-010/021）、字段瘦身（CT-006/015）。

**9. 下一阶段修复顺序（避免返工）？**
1. **输入锁根治理**（CT-001/002，一处根两个症状）；
2. **NPC 快照生命周期**（CT-003/004：suspend/resume + continue_game 补 restore，注意恢复必须在 spawn_all 之后）；
3. **钥匙断供修复**（CT-019：examine 模板与闸门 id 打通——建议 inspect 同时写 `fact_inspected_X` 与语义别名，或事件在黑路穿越时授予 fact_dark_road、热点授予 fact_sticky_note；同步修测试禁止手工注入）；
4. **事件 effects 扩展**（CT-005/013/016：interact 求值 + grant_fact/npc_state/item_state 效果）；
5. **对话维度**（CT-022/023：said 记录 + 现实/记忆 variants）；
6. 反馈层（CT-007/008/012）与手机（CT-011）；

顺序理由：1/2 是多症状共同根；3 在 4 之前（事件 grant_fact 需要钥匙命名规范先定）；对话维度(5)依赖 NPC 记忆(2)与事件(4)先行——照此推进可避免"先写对话内容再改数据结构"的返工。

## 三、结论一句话

COMET 当前是**一台校准良好的单线因果机器**（玩家移动→世界切换→环境反馈→存档恢复），外加**半套信息获取系统**（认知本体可靠、通往对话的钥匙断了一半）和**一群没有大脑的 NPC**。先修五个 P1，闭环就成立；其余按批次走，不必推倒任何现有系统。
